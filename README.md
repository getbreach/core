# Breach

Несёт произвольный трафик (WireGuard, Hysteria2, …) через **TURN-релеи
мессенджеров**, маскируя его под WebRTC-звонок. Аналог `vk-turn-proxy`: креды на
релей добываются из механизма звонков мессенджера, а на проводе это выглядит как
соединение с разрешённым сервисом звонков, а не с произвольным IP.

```
[WireGuard/Hysteria]     breach-client            TURN-релей          breach-server      [WG/Hysteria-сервер]
  сторона цензуры    минт кредов + пул                              VPS :48000              на VPS
       ──udp──>      DTLS-SRTP стримов  ──relay (ChannelData)──>  расшифровка → бэкенд ──> интернет
```

Всё здесь построено реверс-инжинирингом пакетного протокола мессенджеров и
поведения их TURN. **Для образовательных / исследовательских целей.**

## Провайдеры

| Провайдер | TURN-инфра | Минт |
|---|---|---|
| **MAX** | OK/VK (`155.212.x:19302`, `okcdn.ru`) | конференция (никого не будит) или 1:1-звонок |
| **WB** | своя (`176.101.92.x:3478`) | тихий — собеседник звонка не получает |

Инфраструктура у провайдеров **разная**. MAX — государственный мессенджер,
который в РФ не заблокируют, поэтому его TURN — устойчивый неблокируемый релей.

## Компоненты

| Каталог | Что |
|---|---|
| `breach/` | сам туннель: `breach-client` (минтит креды, открывает пул DTLS-SRTP-стримов поверх TURN-аллокаций) и `breach-server` (публичный UDP-эндпоинт → WireGuard/Hysteria/SOCKS5) |
| `turnprobe/` | пробник TURN-релея + бенчмарк пропускной/троттлинга |
| `docs/` | руководства: деплой, провижининг сервера, Android-клиент |

## Как это работает

1. **Минт** — логин, затем добыча TURN-кредов из механизма звонков (у MAX —
   групповая конференция, никого не беспокоит; у WB — тихий звонок, без
   уведомления собеседнику). Креды живут ~8 ч.
2. **Релей** — с этими кредами открываются TURN-аллокации и `ChannelBind` к
   серверу; трафик идёт через них как ChannelData.
3. **Анти-троттл** — TURN режет однонаправленный релей; низкочастотный
   двусторонний keepalive на каждой аллокации держит её как симметричный звонок.
   Квота аллокаций на кред (~6–8), масштаб — минтить больше кредов.
4. **Маскировка** — на каждой аллокации настоящий DTLS-хендшейк, затем SRTP-медиа,
   так что след на проводе — это WebRTC-звонок.

## Быстрый старт

**Сервер (VPS за рубежом)** — собирать ничего не надо, exit-контейнер
(breach-server + wireguard-go + sing-box/Hysteria2) опубликован в GHCR как
`ghcr.io/getbreach/breach-exit`:

```bash
scp breach/deploy/install.sh root@vps: && ssh root@vps sh install.sh
# печатает готовый блок клиента; добавить ещё пользователей:
ssh root@vps docker exec breach-exit provision-client phoneB
```

Compose, env-переменные, Hy2-only, апгрейды — в [`breach/deploy/README.md`](breach/deploy/README.md)
и (по-русски) [`docs/deploy-ru.md`](docs/deploy-ru.md).

Запуск руками:

```bash
# сервер: WireGuard на udp/51820 + NAT, затем
cd breach && go build -o bin/breach-server ./cmd/server
./bin/breach-server -listen :48000 -wg 127.0.0.1:51820

# клиент (сторона цензуры)
go build -o bin/breach-client ./cmd/client

# проще всего — интерактивный мастер: спросит провайдера (MAX/WB), проведёт
# логин (SMS у MAX, ссылка+callback у WB), спросит адрес сервера и режим,
# запишет готовый config.json и предложит сразу стартовать. Он запускается сам
# при первом запуске без конфига, либо принудительно:
./bin/breach-client -setup
# дальше — просто (конфиг уже полный, флаги не нужны):
./bin/breach-client

# вручную (MAX): получить токен по SMS и заполнить конфиг
./bin/breach-client -login +7XXXXXXXXXX > config.json   # спросит код из SMS
# дописать "server"/"wgListen" в config.json, затем
./bin/breach-client -config config.json
```

Полная обвязка WireGuard (в т.ч. исключение петли маршрутизации) — в
[`breach/DEPLOY.md`](breach/DEPLOY.md); детали протокола и провайдеров — в
[`breach/README.md`](breach/README.md); WB-провайдер и stream-режим (SOCKS5 без
root) — там же. Встраивание в Android-приложение — [`docs/android-client.md`](docs/android-client.md),
деплой и управление из приложения — [`docs/server-provisioning.md`](docs/server-provisioning.md).

## Статус

Рабочий прототип, проверен сквозь на живой инфраструктуре (телефон → TURN → VPS →
интернет), два провайдера (MAX, WB), несколько клиентов на один сервер.
Шероховатости: переминт заменяет пул разом (без плавного слива), наивный
round-robin, аккаунт/IP-троттл — реальный потолок (размазывать нагрузку по
аккаунтам/IP).
