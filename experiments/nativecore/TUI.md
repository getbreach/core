# Терминальный интерфейс

`tui` запускает тот же движок внутри одного бинаря и показывает его состояние.
Из корня репозитория `core`:

```sh
sh experiments/nativecore/scripts/build-desktop.sh
sudo ./breach/bin/breach tui -config ./breach/config.macos.json
```

Для локального SOCKS5 root не нужен:

```sh
./breach/bin/breach tui -config ./breach/config.native.json
```

Это отдельный запуск движка. Сначала остановить предыдущий `breach run`, если
он использует тот же порт или управляет системными маршрутами.
Нужен интерактивный терминал; рекомендуемый размер — 100 × 30 символов.
Для вывода в файл или сервисного запуска остаётся `breach run`.

На широком экране панели туннеля, системы, трафика и процесса расположены
в две колонки; в 80 × 24 используется компактная компоновка. Статусы и события
выделены цветом, нагрузка показана полосами, история приёма — графиком.
Используются стандартные Unicode-символы, отдельный шрифт с иконками не нужен.
`NO_COLOR=1` отключает цвет (при sudo: `sudo env NO_COLOR=1 breach tui ...`).

## Что видно

- Состояние запуска, Hy2, переподключения, имя utun или адрес SOCKS5.
- Число действующих и целевых TURN-аллокаций; активные/отклонённые TUN-потоки.
- Режим маршрутов/DNS, способ проверки TLS, время работы.
- Скорость загрузки/отдачи, суммарные байты и пакеты, история скорости приёма.
- Общая загрузка CPU и RAM, load average за 1/5/15 минут.
- CPU и RSS процесса Breach, Go heap, число goroutine, последние сообщения.

Метрики обновляются примерно раз в секунду. `ONLINE` означает готовый локальный
вход и подключённую Hy2-сессию; это не отдельная проверка доступности сайтов.
Строка Network показывает режим настройки, ошибки восстановления выводятся ниже.

Счётчики трафика измеряют зашифрованные Hy2-датаграммы, включая служебный трафик
Hy2/QUIC. Внешние заголовки SRTP/TURN и соединения правила `direct` не входят.
Счётчики сохраняются при переподключении в рамках одного запуска.
CPU процесса: 100% соответствует одному полностью занятому логическому ядру;
общий CPU системы нормирован на 0–100%. RSS относится к основному процессу,
без служебных процессов маршрутов/DNS. Недоступные метрики показаны как `--`.

## Клавиши

| Клавиша | Действие |
|---|---|
| `m` | Переключить TUN ↔ PROXY; подсказка внизу показывает целевой режим |
| `t` | Открыть настройки количества TURN mints/streams |
| `q` / `Ctrl+C` | Остановить движок, дождаться очистки маршрутов/DNS и вернуть терминал |
| `p` | Приостановить/возобновить обновление экрана; трафик продолжает идти |
| `l` | Скрыть/показать журнал |

При изменении размера окна экран перестраивается. Журнал ограничен 100 строками;
управляющие символы удаляются, известные секреты конфига скрываются.

## Горячее изменение TURN-пула

Нажать `t`, изменить `mints` клавишами `-` / `+`, `streams` клавишами `[` / `]`,
затем Enter. Esc отменяет правки. Mints задаются **на аккаунт**, streams —
**на mint**; итоговый размер равен accounts × mints × streams.
Пределы горячей настройки: 1–16 для каждого поля и не более 256 аллокаций суммарно.

Изменение применяется фоновым обработчиком, процесс, SOCKS/TUN и Hy2 не
перезапускаются. Существующие аллокации продолжают передавать трафик, пока
открываются недостающие; при уменьшении лишние аллокации освобождаются.
Неиспользуемые валидные креды сохраняются в памяти. Новые mint-запросы нужны
только при нехватке пригодных кредов; для WB это может означать новый звонок.

В строке TURN видны `M` и `S`, текущий/целевой размер и `applying`, пока запрос
не выполнен. При отказе провайдера сохраняется рабочая часть пула; попытки
повторяются с задержкой. Можно задать меньший размер. Завершение программы
отменяет применение и закрывает также ещё не добавленные аллокации.
Настройки действуют до выхода и сохраняются при переключении SOCKS/TUN;
JSON-конфиг не перезаписывается.

API общего транспорта: `Tunnel.SetPoolLimits(mints, streams) error`,
`Tunnel.PoolLimits() string` (JSON со значениями, target и applied).
Методы используют только общий Go-код и доступны в сборках macOS, Linux,
Windows, Android и iOS. Мобильным приложениям нужно подключить этот API к их UI.

## Переключение TUN / PROXY на macOS

Для обоих режимов запускайте TUI через sudo с `config.macos.json`, как выше.
Нажатие `m` переключает на локальный SOCKS5 (`socksListen`, по умолчанию
127.0.0.1:1080); следующее нажатие возвращает исходные настройки TUN.
PROXY не включает системный прокси macOS: адрес SOCKS5 нужно выбрать в приложении.
Настройки на диске не перезаписываются, после нового запуска используется
исходный `inbound` из конфига.

Смена режима заменяет только локальный вход: сначала завершается очистка
его маршрутов, DNS и порта, затем запускается SOCKS5 или TUN. TURN-пул,
действующие креды и Hy2-сессия остаются живыми. Само нажатие `m` не запрашивает
новые креды; их истечение, отказ relay или реальная смена сети по-прежнему
могут потребовать обновления транспорта.
Потоки старого локального входа закрываются, но общая Hy2-сессия, счётчики трафика
и uptime сохраняются. Полностью транспорт закрывается при выходе из TUI.
Во время перехода показан `SWITCHING`; повторные `m` игнорируются, `q`/Ctrl+C
отменяют переход и завершают программу после очистки.

Права, платформа и конфиг проверяются до отключения работающего режима.
Без sudo попытка включить TUN оставляет прокси работающим. При запуске из
SOCKS-конфига для автоматического TUN нужны `routing.dns.fakeIP: true` и
постоянный `stateFile`; проще использовать готовый macOS TUN-конфиг.
Если новый режим не запустился, TUI пытается вернуть предыдущий режим,
если тот был ONLINE перед переключением. Ошибка остаётся на экране. При ошибке
восстановления автоматические повторы прекращаются; можно выбрать другой режим
через `m` или выйти. Переключение на TUN других ОС пока не реализовано.

## Платформы и проверки

Полный набор системных метрик реализован для macOS. Linux и Windows пока показывают
состояние движка и Go runtime без системных CPU/RAM. Для Windows добавлен адаптер
VT-консоли с восстановлением настроек ввода/вывода и кодировки; рекомендуется
Windows Terminal. Ввод использует [ReadConsoleInputW](https://learn.microsoft.com/en-us/windows/console/readconsoleinput).
Windows TUI проверен кросс-компиляцией, интерактивная проверка на устройстве ещё нужна.
Мобильного TUI нет; общий движок и API пула продолжают собираться.
Darwin-код метрик исключён из сборок других ОС.

2026-09-19: прошли race-тесты, vet и проверки переносимости. В псевдотерминале
проверены реальный TURN/Hy2 VPS и HTTPS 200 через SOCKS5, пауза, изменение размера,
выход через `q`, Ctrl+C во время подключения и восстановление настроек терминала.
Полный TUN ранее проверен отдельно; запуск именно TUI с полным захватом сети
нужно проверить на устройстве с sudo.

Переключение: тесты проверяют ожидание cleanup, повторные нажатия, отмену перехода,
сохранение настроек и восстановление настоящего SOCKS-слушателя/Hy2 после
моделируемой ошибки TUN. В живом TUI проверено, что `m` без root не прерывает
HTTPS через прокси. Полный переход с системными маршрутами требует проверки с sudo.

Сохранение транспорта проверено отдельно на реальном VPS под `-race`: два
последовательных локальных SOCKS-входа дали HTTPS 200, сохранились 12 аллокаций,
число mint-запросов осталось 3, Hy2-аутентификация была одна. Локальный тест
дополнительно проверяет повторное использование порта, рост общих счётчиков и
сохранение сессии после ошибки открытия входа. Обнаруженная живым прогоном гонка
между SRTP data/keepalive исправлена; параллельное шифрование покрыто тестом
с переходом счётчика RTP через 65535.

Горячая настройка проверена на реальном VPS с `-race`: пул прошёл
12 → 6 → 4 → 6 → 12 → 16 → 12 аллокаций. Одно HTTPS keep-alive соединение
и одна аутентифицированная Hy2-сессия пережили весь цикл. Возврат прежних лимитов
использовал кеш; добавление четвёртого mint потребовало ровно один новый запрос.
В PTY проверены редактор, отмена и применение streams 4 → 3 → 4.
Локальные тесты покрывают уменьшение, расширение, нехватку квоты, конкурентные
запросы, удаление умершего потока во время resize и остановку незавершённого resize.
