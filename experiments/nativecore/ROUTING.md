# Правила маршрутизации нового ядра

Реализовано 2026-09-17. SOCKS5 и gVisor/TUN используют один `routing.Router`.
Внутри туннеля остаётся только Hy2; `direct` открывает обычный сокет вне VPN,
`block` возвращает отказ. Обрыв Hy2 не переключает соединение на direct.

## CLI

```sh
sh scripts/build-desktop.sh
../../breach/bin/breach-native -config /path/to/native.json
```

Добавить в существующий Hy2-конфиг:

```json
{
  "routing": {
    "defaultAction": "tunnel",
    "dns": {
      "fakeIP": true,
      "upstream": "1.1.1.1:53",
      "stateFile": "/absolute/private/path/native-fakeip.jsonl"
    },
    "rules": [
      {"domains": ["full:ads.example.org"], "action": "block"},
      {"domains": ["domain:example.org"], "ports": "443,8000-8010", "network": "tcp", "action": "tunnel"},
      {"ips": ["192.168.0.0/16", "fd00::/8"], "action": "direct"},
      {"domains": ["geosite:telegram"], "action": "tunnel"},
      {"ips": ["geoip:ru"], "action": "direct"}
    ],
    "setFiles": {
      "geosite-telegram": "/path/to/geosite-telegram.json",
      "geoip-ru": "/path/to/geoip-ru.json"
    }
  }
}
```

Это фрагмент, а не замена настроек password/TLS/remote/inbound. При отсутствии
`routing` всё по-прежнему уходит в Hy2. Порядок правил важен: первое совпадение
побеждает, разные условия одного правила объединяются AND, значения внутри
одного поля — OR. Неизвестный action, плохая регулярка, неверный порт или
отсутствующий список останавливают запуск; правило не пропускается молча.

Домены: `full:` точное имя, `domain:` имя и поддомены, `keyword:` подстрока,
`regexp:` Go/RE2-регулярное выражение. Имя без префикса — **суффикс домена**.
Домены нормализуются в lowercase ASCII/IDNA; regex применяется к нормализованному
имени. Это собственный формат Breach, не полная совместимость с JSON Xray.
IP: одиночный адрес или CIDR. Порты: `53,443,1000-2000`. Network: `tcp`, `udp`
или отсутствие ограничения. На UDP маршрут выбирается для каждого адресата,
не один раз на всю SOCKS-ассоциацию. До 64 адресатов на ассоциацию.

### DNS и FakeIP

При `fakeIP: true` TCP/UDP-пакеты на порт 53 перехватываются локально. A/AAAA
получают виртуальные адреса из `198.18.0.0/16` / `fd00:198:18::/96`. Router
восстанавливает домен перед применением правил и подменяет обратный UDP-адрес,
чтобы приложение получило ответ от ожидаемого виртуального адреса.

- `stateFile` хранит append-only соответствия с правами 0600, без переиспользования
  адресов: после переподключения старый FakeIP не назначается другому домену.
  Рекомендуется отдельный постоянный файл для каждого экземпляра ядра.
- До 65534 имён на состояние. При исчерпании выдаётся SERVFAIL; нет молчаливого
  переназначения адресов. Повреждённый журнал вызывает ошибку запуска.
- Без stateFile соответствия живут только в памяти; после перезапуска нужно
  очистить DNS-кеш приложений. Не применять этот вариант как постоянную поставку.
- Реальные A/AAAA для IP-правил, прямых доменных соединений и UDP разрешаются
  **через Hy2**, не через системный DNS. Кеш ограничен 4096 имён, учитывает TTL
  (не более 300 с). DNS upstream — IP:port, обмен по TCP через туннель.
- Остальные DNS-типы пересылаются upstream. HTTPS/SVCB в FakeIP-режиме получают
  пустой ответ, чтобы адресные hints не обходили связь с доменом.
- DNS-перехват — внутренний сервис перед обычными правилами потоков. Прямое
  доменное соединение всё ещё требует доступного Hy2 для разрешения имени.
- DoH/DoT приложений не расшифровывается; если приложение обошло системный DNS
  или использует жёстко заданный IP, действуют IP/default-правила. Нельзя обещать
  определение имени любого соединения только по его IP.

### Прямые соединения в TUN

Android передаёт `VpnService.protect` в native engine; отказ protect прерывает
соединение. Linux CLI требует `directInterface`, например `"eth0"`, если в
TUN-профиле есть direct. Сокеты привязываются через SO_BINDTODEVICE. На этом
физическом интерфейсе должен сохраняться рабочий маршрут вне TUN.
Автоматическая настройка маршрутов/DNS и kill switch пока не входят в CLI.
SOCKS-режим без системного TUN не требует directInterface.

Обновление 2026-09-18: macOS поддерживает utun и `autoRoute`, с привязкой внешних
сокетов через IP_BOUND_IF/IPV6_BOUND_IF и временным системным DNS.
Настройка и статус системных проверок: [MACOS.md](MACOS.md).

## Geosite / GeoIP без sing-box

Нативный JSON списка:

```json
{"domains":["domain:example.org","full:one.test","regexp:^api[0-9]+\\.test$"]}
```

```json
{"ips":["192.0.2.0/24","2001:db8::/32"]}
```

Можно встроить такие объекты в `routing.sets` под ключом `geosite-NAME` или
`geoip-NAME`, либо использовать `setFiles`. Бинарный `.srs` не читается: нужен
явный перенос в JSON. Встроенные Android-списки уже перенесены; старые файлы
сохранены. Пользовательские URL в новой сборке принимают native JSON.

Конвертер V2Ray/Xray `.dat` находится в самом CLI и Android AAR:

```sh
../../breach/bin/breach-native convert-geodata \
  -input /path/to/geosite.dat -kind geosite -category telegram -out /path/to/sets
../../breach/bin/breach-native convert-geodata \
  -input /path/to/geoip.dat -kind geoip -category ru -out /path/to/sets
```

Без `-category` конвертируются все категории. Обрабатываются domain/full/regex/
keyword и CIDR. Фильтрация geosite по атрибутам и inverse GeoIP не реализованы;
запрос неизвестной категории / inverse GeoIP отклоняется явно. Sing-box и Xray
для работы конвертера не нужны.

## Разделение приложений

В `android-native` подключено к существующим настройкам:

- INCLUDE — через VPN только выбранные пакеты;
- EXCLUDE — через VPN всё, кроме выбранных;
- OFF — без отбора приложений.

Отбор выполняет VpnService.Builder до packet bridge, затем правила доменов/IP
действуют на попавший в VPN трафик. Пустой INCLUDE и несуществующий выбранный
пакет приводят к ошибке; не превращаются в «весь трафик через VPN».
В режиме только SOCKS выбор приложения определяется настройкой прокси в нём.
Правила и списки приложений применяются при следующем подключении.

Общий роутер компилируется для пяти ОС. **Per-app адаптеры Windows/Linux/macOS
этим изменением не реализованы**; универсальный PID/package из IP-пакета получить
нельзя. Для iOS остаются ограничения управляемого per-app VPN. Сборка ядра не
означает готовности этих системных функций на всех устройствах.

## Проверки

- `go test -race ./...`, `go vet ./...`: правила/порядок, geodata, защита direct,
  отсутствие fallback, раздельные UDP-адресаты, перезапуск FakeDNS, остановка.
- IP-пакеты через второй netstack → FakeDNS → FakeIP → правила → настоящий Hy2
  → TCP/UDP echo. Отдельные IPv4/IPv6 Hy2-тесты из базового прототипа сохранены.
- Android engine: тест SOCKS direct/block с protect, прежние тесты reconnect/TUN fd.
- Собраны Android AAR/APK, ядро для пяти ОС, iOS C-архив. Новая Android-сборка
  на телефон не устанавливалась; её пользовательский VPN-сценарий не проверен.
- Живой MAX TURN/VPS: HTTPS tunnel=200, loopback HTTP direct=200,
  block=отказ SOCKS, FakeDNS → FakeIP → domain routing → HTTPS=200.
  TLS использовал явный legacy insecure как в предыдущем опыте. Исходный конфиг
  не изменён; временные секреты удалены и процессы остановлены.
