# Native core: Hysteria2 внутри TURN, локальный SOCKS5 или TUN

Реализация [плана перехода](../../docs/own-core-plan.md).
Единый CLI `breach` использует **только Hysteria2** внутри туннеля:

```text
приложение → локальный SOCKS5 ─┐
                             ├→ встроенный Hy2 → внутренний UDP pipe → TURN-библиотека
приложение → TUN → netstack ──┘                     → SRTP/TURN → VPS Hy2 → Интернет
```

SOCKS5 завершается на клиенте. На VPS не нужен SOCKS-сервер, `qtun` или
`PROTO=socks`. TURN, Hy2 и локальные входы работают в **одном процессе**.
Пока остаётся приватная передача UDP через loopback на случайном порту; отдельный
`breach-client` не требуется. Прямой in-memory PacketConn остаётся оптимизацией.
Существующие приложения, сервер и их конфиги этот эксперимент не переключает.

## Базовый Hy2-прототип: что проверено (2026-09-16)

- Живой MAX silent mint, 4 TURN-аллокации, существующий Hy2 VPS: **без sing-box
  на клиенте** работают HTTPS и DNS по TCP/UDP через локальный SOCKS5.
- `example.com`: HTTP 200, 559 байт, 0.291 с.
- Cloudflare download 1 МиБ: HTTP 200, 2.033 с, 515745 байт/с (~4.13 Мбит/с).
- DNS `example.com` через `1.1.1.1:53`: ответы по TCP и UDP; `decFail=0` у TURN.
- Это один короткий прогон. Предыдущий sing-box baseline: 1 МиБ за 5.005 с
  (~1.68 Мбит/с); разные сессии/состояние сети не позволяют заключить, что новое
  ядро быстрее. CPU, RSS и батарея не измерялись.
- В обоих живых опытах явно использован legacy `insecure: true` для существующего
  самоподписанного сертификата. Проверка доверенного pin и отклонение неверного
  pin/пароля отдельно проходят на локальном Hy2-сервере. Автоматического TLS fallback нет.
- Исходный конфиг не изменён, временные секреты удалены, дочерние процессы остановлены.

Локальные `go test -race ./...` и `go vet ./...` проходят на macOS amd64:

- IP-пакеты → netstack → **настоящий Hy2-сервер** → TCP/UDP fixtures, IPv4/IPv6;
- UDP-фрагментация 3000 байт, несколько потоков к одному адресу, DNS TCP/UDP;
- SOCKS5 CONNECT с доменным именем и UDP ASSOCIATE через Hy2;
- отмена подключения/UDP receive, закрытие прокси со stalled SOCKS-клиентом;
- ошибки аутентификации/TLS, закрытие сокета после неудачной попытки;
- Hy2 через UDP pipe без legacy-маркера, фильтрация постороннего источника;
- сохранены контрольные тесты старого `qtun`: half-close, UDP 0/4096 байт,
  лимиты потоков, idle timeout и остановка packet bridge. Они **не доказывают**
  поддержку этих возможностей в Hy2 (ограничения ниже).

Сборка ядра проверена для Linux/Windows/macOS amd64/arm64 и Android/iOS arm64.
Проверена линковка iOS C-архива с SDK Xcode и Android `.so` с NDK 29, API 26.
Это не запуск VPN на устройстве. Linux kernel TUN-тест переведён на Hy2 и
компилируется; в этой macOS-среде не запускался. CI добавлен, но удалённый запуск
пока не выполнялся.

## Состав и зависимости

| Пакет | Назначение |
|---|---|
| `hy2` | Официальный Hy2-клиент, TLS/pin, ограничение зависших dial, отмена UDP |
| `outbound` | Единый TCP/UDP-контракт для локального прокси и packet bridge |
| `inbound` | Локальный SOCKS5 через существующий пакет `breach/socks5` |
| `bridge` | IP-пакеты, gVisor netstack, TCP/UDP-forwarding, лимиты и счётчики |
| `packetio` | Пакетное устройство, отменяемый насос; Linux TUN и macOS utun |
| `systemtun` | Временные macOS маршруты и DNS, откат и освобождение ресурсов |
| `transport` | Hy2 UDP напрямую или через loopback pipe, без маркеров `qtun` |
| `reconnect` | Замена Hy2-сессий, ожидание готовности, backoff, отмена |
| `engine` | Общий жизненный цикл TURN/Hy2/роутера/SOCKS/TUN |
| `cmd/breach` | Единый CLI: run, check, convert-geodata |
| `cmd/nativeprobe` | Совместимость с прежним CLI и mode=pipe |
| `cmd/linkprobe` | Проверка мобильной линковки; не финальный мобильный API |
| `internal/hy2test` | Только локальный тестовый сервер, не production exit |
| `integration` | Linux kernel → TUN → bridge → Hy2 → TCP/UDP/DNS fixtures |

Закреплены `apernet/hysteria/core/v2 v2.12.3`, его `apernet/quic-go` и upstream
`gvisor.dev/gvisor` на ревизии `0916ab1e1204`. Требуется Go ≥ 1.26.3,
проверено с Go 1.27.1. Новый бинарник не импортирует sing-box/libbox,
`breach/qtun`, SagerNet QUIC или WireGuard. SagerNet присутствует в модуле
из-за **контрольных legacy-тестов**, а не в новом рабочем пути.

`hy2.Dial` владеет переданным PacketConn и закрывает его даже при ошибке.
Контекст Dial ограничивает аутентификацию; вызывающий код закрывает успешный
Client после bridge/proxy. Отмена UDP ReadFrom закрывает эту ассоциацию.
Bridge владеет потоками и netstack, `packetio.Run` — устройством.
По умолчанию у bridge 256 потоков и очередь 256 пакетов. Буферы копируются.

## Прежний запуск двумя процессами (совместимость)

1. В **копии** обычного TURN-конфига поставить `wgListen: "127.0.0.1:51821"`,
   `socks: ""`, `mints: 1`, `streams: 4`, `mintMode: "silent"`.
   Старое имя `wgListen` здесь обозначает UDP pipe; WireGuard не используется.
   Запустить обычный `breach-client -config /path/to/turn-copy.json`.
2. Собрать новый клиент:

   ```sh
   go build -o /tmp/breach-nativeprobe ./cmd/nativeprobe
   ```

3. Создать отдельный файл с правами `0600`:

   ```json
   {
     "mode": "pipe",
     "remote": "127.0.0.1:51821",
     "password": "YOUR_HY2_PASSWORD",
     "tls": {
       "serverName": "YOUR_HY2_SNI",
       "certSha256": "64_HEX_CHARACTERS_FROM_A_TRUSTED_SERVER_PROFILE"
     },
     "inbound": "socks",
     "socksListen": "127.0.0.1:1080"
   }
   ```

   Для сертификата доверенного CA достаточно `serverName`, без `certSha256`.
   Для существующего legacy-профиля с отключённой проверкой допускается явное
   `"insecure": true` **вместо** pin; такой запуск пишет предупреждение.
   Pin — SHA-256 DER сертификата Hy2, не сертификата бывшего `qtun`.

4. Запустить и проверить:

   ```sh
   /tmp/breach-nativeprobe -config /path/to/native.json
   curl --socks5-hostname 127.0.0.1:1080 https://example.com
   ```

SOCKS слушает только loopback. Доменные имена в SOCKS-запросах передаются exit
для разрешения; сам системный DNS этим режимом не меняется. UDP требует поддержки
SOCKS5 UDP ASSOCIATE приложением. При обрыве Hy2 CLI теперь переподключается,
сохраняя локальный слушатель; оборванные потоки переоткрывает приложение.
Режим `direct` адресует непосредственно Hy2-сервер для стенда,
а не публичный SRTP-порт Breach.

## Linux TUN

В том же конфиге поставить `"inbound": "tun"`, `"interface": "breach0"`,
`"mtu": 1280`. Запустить CLI с правами создания TUN. После аутентификации:

```sh
sudo ip addr add 198.18.0.1/30 dev breach0
sudo ip link set breach0 mtu 1280 up
sudo ip route add 1.1.1.1/32 dev breach0
dig @1.1.1.1 example.com
```

Для первого опыта использовать Linux VM и выбранные тестовые маршруты.
Default route, системный DNS, kill switch и автоматический cleanup маршрутов
ещё не реализованы. TURN, MAX/WB, служебный DNS и exit должны оставаться вне TUN.
На других ОС реализован пакетный контракт и проверена сборка; системные VPN-адаптеры
ещё предстоит подключить.

## Ограничения перед полной заменой ядра

- **TCP half-close**: публичный API Hy2 v2.12.3 не предоставляет CloseWrite,
  серверный copy заканчивается на первом EOF. Для протоколов, где клиент завершает
  запись и затем ждёт ответ, нет гарантии сохранения ответа. Нужна доработка;
  не объявлять полную совместимость с прежним qtun.
- **UDP**: пустые пакеты и сообщения >4096 байт с адресом/заголовком пока не
  поддерживаются upstream; адаптер возвращает ошибку при отправке. Тестовая
  фрагментация 3000 байт проходит, прежние тесты 0/4096 для qtun сохранены отдельно.
  Это ограничение реализации, а не обещание максимального размера протокола Hy2.
- TCP dial ограничен 10 с для вызывающего кода, но upstream не даёт отменить
  отдельную зависшую negotiation. Одновременно допускается до 32; полный Close
  освобождает остаток. Нужна отмена stream для production.
- Нет общего `engine/relay`, восстановления сессии и прямой связи с TURN-пулом.
- Нет HTTP-прокси и автоматической системной маршрутизации.
  DNS/FakeIP и geosite/geoip реализованы: см. [ROUTING.md](ROUTING.md).
- Android VpnService/AAR подключены в `../../../android-native`; новый APK собран,
  запуск на телефоне ещё не проверен. Windows Wintun/службы и Apple Network Extension/GUI нет.
- На сервере ещё остаётся нынешний Hy2 backend; перенос в `breach-server`,
  собственные политика/статистика и отказ от Clash API — следующие этапы.
- TCP/UDP proxy stack не является raw IP VPN; произвольные IP-протоколы не переносятся.

Стабильная поставка всё ещё содержит старые компоненты. Их удаление выполняется
после системных тестов и миграции клиентов, не вместе с первым экспериментом.
