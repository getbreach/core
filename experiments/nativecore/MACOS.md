# macOS TUN

Обновлено 2026-09-19: системный utun → gVisor → routing → Hy2 → TURN.
`utun` создаётся через kernel control API; внешний драйвер не нужен.
Поддерживается macOS amd64/arm64, iOS использует отдельный платформенный адаптер.

## Конфиг и запуск

В копии единого конфига:

```json
{
  "inbound": "tun",
  "interface": "auto",
  "autoRoute": true,
  "mtu": 1280,
  "routing": {
    "defaultAction": "tunnel",
    "dns": {
      "fakeIP": true,
      "stateFile": "/absolute/private/path/native-macos-fakeip.jsonl"
    }
  }
}
```

Это фрагмент: сохранить существующие turn/password/TLS и правила routing.
`breach check -config ...` проверяется без root, `breach run -config ...`
для создания интерфейса и настройки сети запускается через sudo.
Сборка: `sh scripts/build-desktop.sh`.

`interface: auto` выбирает свободный utunN. Можно явно задать utunN;
старое значение breach0 также означает автоматический выбор на macOS.
`directInterface` по умолчанию определяется из физического default route;
можно явно задать en0/en1. Если default route уже указывает на другой utun,
автоматический выбор отклоняется, чтобы не создавать петлю между VPN.

## Маршруты, DNS и завершение

- Добавляются маршруты IPv4 0/1, 128/1 и IPv6 ::/1, 8000::/1 на utun.
  Существующий default gateway и более специфичные LAN/служебные маршруты
  сохраняются. Это не kill switch и не обещание захвата локального трафика.
- TURN, mint/DNS транспорта и direct-сокеты используют IP_BOUND_IF/IPV6_BOUND_IF,
  чтобы внешние соединения шли через физический интерфейс, а не обратно в utun.
  До установки маршрутов utun создаётся отдельный default с `-ifscope` для
  физического интерфейса, если такого маршрута ещё нет. Одной привязки сокета
  недостаточно: после добавления /1 macOS может не найти прежний unscoped /0
  для bound-сокета. Существующие scoped-маршруты не присваиваются и не удаляются.
  Автоматический выбор интерфейса обновляется при новых сокетах с кешем 2 секунды.
- Адреса интерфейса: 198.19.255.1 → 198.19.255.2, fd00:198:19::1/126.
  Они отделены от выдаваемого диапазона FakeIP 198.18.0.0/16.
- Временная запись DNS в SystemConfiguration указывает на 198.19.255.2;
  порт 53 обрабатывает наш роутер. Постоянные настройки DNS сетевой службы
  не перезаписываются. DoH/DoT приложений не расшифровывается.
- DNS-запись принадлежит живой scutil-сессии. При SIGKILL родителя закрывается
  stdin pipe, scutil выходит, configd удаляет временную запись. При закрытии
  последнего utun fd ядро удаляет интерфейс и привязанные к нему маршруты.
- При нормальной остановке сначала убираются DNS/наши маршруты, затем utun.
  При ошибке настройки откатываются только успешно добавленные маршруты.
  Существующие совпадающие маршруты не заменяются; ошибка add прерывает запуск.
- Физические scoped defaults принадлежат служебному процессу из того же
  бинаря (`internal-route-guardian`). Он сам выполняет add и ведёт список
  созданных маршрутов. EOF на stdin после штатного выхода или SIGKILL основного
  процесса запускает очистку. Отдельная сессия защищает его от терминального
  Ctrl+C; SIGPIPE не прерывает cleanup при потере канала ответа родителю.
- Перед удалением проверяются интерфейс, шлюз и scoped-флаг: уже удалённые или
  заменённые маршруты не трогаются. Существовавшие до запуска маршруты не
  присваиваются. При штатной остановке scoped defaults удаляются после DNS и
  маршрутов utun. Принудительное убийство самого guardian через SIGKILL или
  выключение ОС не даёт выполнить пользовательский cleanup.
- Если владелец DNS или guardian неожиданно завершится, движок останавливает TUN.

Каждые 2 секунды проверяются интерфейсы и физический шлюз. Смена шлюза при
неизменном локальном IP тоже обнаруживается. Перед сбросом TURN/Hy2 обновляются
наши scoped defaults; исчезнувшие маршруты восстанавливаются. Если физической
сети временно нет, проверка повторяется, TUN/FakeIP сохраняются. После
восстановления сети транспорт сбрасывается один раз. Пауза часов более 10 секунд
считается пробуждением и также вызывает переподключение после проверки маршрутов.
Существующие соединения через старую Hy2-сессию не переносятся.

## Проверки

Обычные: `go test -race ./...`, `go vet ./...`, кросс-компиляция для пяти ОС.
Есть тесты framing utun (IPv4/IPv6), отмены блокирующего чтения, привязки
реальных сокетов к интерфейсу, отката настройки и повторного cleanup.

Системные тесты: `sh scripts/macos-tun.sh` (запрашивает sudo).
Они добавляют только тестовые host routes 198.19.99.1 и 2001:db8:beef::1,
проверяют TCP/UDP через kernel utun → gVisor → настоящий локальный Hy2,
и DNS для специальных доменов .invalid. В DNS-тесте дочерний процесс убивается
SIGKILL, после чего проверяется удаление его записи. Default route и DNS
этими тестами не переключаются. Дополнительный `TestMacOSScopedBypass` направляет
только 203.0.113.0/24 в utun и проверяет, что scoped-запрос маршрута по-прежнему
находит физический шлюз; временный scoped default удаляется после теста.
Отдельный шаг добавлен в macOS CI.

Полный захват пользовательского трафика, реальный VPS, сон/пробуждение
и совместимость с другими VPN проверяются отдельно на устройстве.

Статус на 2026-09-19: пользователь подтвердил работу полного macOS TUN
через реальный TURN/Hy2 VPS после исправления scoped default и обработки
`route get`, возвращающего код 0 при отсутствии маршрута.

Для новых изменений есть тесты смены шлюза, интерфейса, пропадания сети,
восстановления удалённого маршрута и сохранения чужих маршрутов. Непривилегированный
тест действительно убивает процесс-родитель через SIGKILL, пока guardian
выполняет добавление в модель таблицы маршрутов, и проверяет последующую очистку.
`TestRouteGuardianKernelCleanup` проверяет обычный выход и SIGKILL родителя
с настоящим scoped default; он запускается через sudo в macOS CI вместе с
остальными системными тестами. Реальный сон и смену Wi-Fi на пользовательском
устройстве нужно проверить отдельно.

При работающем TUN выполнить `sh scripts/macos-diagnose.sh` во втором терминале.
Диагностика не требует sudo и не меняет настройки: показывает системный DNS,
маршруты и счётчики utun, проверяет DNS по UDP/TCP и HTTPS отдельно по IP,
с системным разрешением имени и через FakeIP. Конфиг и журнал FakeIP не читает.
