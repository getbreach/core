# Единый Breach CLI

Реализовано 2026-09-17: один исполняемый файл и один конфиг для
MAX/WB TURN → DTLS-SRTP → Hy2, с локальным SOCKS5 или Linux TUN/gVisor.
Для запуска не нужны sing-box, WireGuard, qtun или отдельный breach-client.

```sh
sh scripts/build-desktop.sh
../../breach/bin/breach check -config /absolute/path/config.native.json
../../breach/bin/breach run -config /absolute/path/config.native.json
```

`check` проверяет структуру, учётные поля, TLS-настройки и правила без подключения.
Проверка действительности пароля и сертификата происходит при `run`.
`convert-geodata` сохранён, см. [ROUTING.md](ROUTING.md).

## Конфигурация

[config.example.json](config.example.json) — шаблон без действующих секретов.
В объект `turn` переносятся поля существующего транспортного конфига:
provider, token/deviceId/accounts, server, mintMode, streams, mints, DNS,
TURN transport и cache. Для WB используются wbSession/wbChat/wbCallee.
Старые непустые socks/socksToken/socksPin отклоняются: они выбирали другой
протокол до VPS. Локальный SOCKS задаётся верхнеуровневым `socksListen`.

- `mode: turn` — обычный единый запуск; `remote` не задаётся.
- `mode: pipe` — совместимость с отдельным TURN-процессом; нужен loopback `remote`.
- `mode: direct` — Hy2 напрямую по `remote`, без TURN (лабораторный режим).
- `startupTimeoutSeconds`: 1–600, по умолчанию 90; ограничивает ожидание Hy2.
- SOCKS доступен только на loopback, TCP CONNECT и UDP ASSOCIATE.
- TUN пока Linux, маршруты/MTU/DNS задаются вручную. `directInterface` нужен
  для исходящих внешних сокетов и direct-правил, чтобы избежать петли в TUN.
  На выбранном физическом интерфейсе должен сохраняться рабочий маршрут.
- Пути к cache, WB session, наборам правил и FakeIP state лучше задавать
  абсолютными: относительные пути отсчитываются от рабочей директории процесса.

Частный `breach/config.native.json` создан отдельно от старого конфига,
с правами 0600 и исключён из Git. Он сохраняет явно включённый legacy insecure
для текущего VPS. Для обычной проверенной TLS-схемы используйте доверенный CA
либо заранее известный certSha256, как описано в README.

## Что происходит при обрыве

1. TURN-библиотека обновляет credentials, удаляет умершие аллокации и пополняет пул.
2. Потеря Hy2 обнаруживается через завершение UDP-ассоциации наблюдения; при
   молчаливом исчезновении peer действует QUIC idle timeout около 30 секунд.
3. Рабочий поток создаёт свежий UDP-сокет и новую Hy2-сессию. Таймаут попытки
   15 секунд, пауза растёт с 1 до 15 секунд, с jitter ±20%.
4. SOCKS-слушатель, TUN, роутер и таблица FakeIP остаются на месте. Новый поток
   ждёт готовности не больше 10 секунд и собственного более короткого deadline.
5. Старые TCP-потоки и UDP-ассоциации завершаются. Их должен переоткрыть клиент;
   ядро не повторяет уже отправленные данные и не переключается на direct.

Интерфейсы и адреса проверяются каждые 2 секунды. Изменение либо большой скачок
времени после сна вызывает пересоздание TURN-аллокаций и сброс Hy2. Смена только
маршрута при неизменных адресах может быть замечена лишь health/idle-проверками.
Тесты реального сна и переключения физических сетей на устройствах ещё нужны.

Ошибки пароля, сертификата, отключённого UDP и локальные TLS/QUIC internal errors
останавливают движок. Сетевые ошибки повторяются. Ctrl+C/SIGTERM отменяет ожидание,
закрывает входы, Hy2, прямые потоки и TURN. Некоторые операции mint/TURN в старой
библиотеке завершаются по собственным таймаутам, поэтому остановка во время mint
может занять дольше отмены одной Hy2-аутентификации.

## Технические границы

TURN-пул переиспользуется из `breach/mobile`, без копирования протокольного кода.
Между ним и Hy2 пока внутренний UDP loopback на случайном порту, а не очередь
в памяти. Всё работает внутри одного процесса; второй executable не запускается.
В библиотеке TURN остаются глобальные DNS/socket hooks, поэтому движок разрешает
только один встроенный TURN-клиент на процесс и восстанавливает прежний resolver
при остановке. Эти hooks ещё нужно сделать независимыми для нескольких экземпляров.

Общий engine компилируется под Linux, Windows, macOS, Android и iOS.
Это не добавляет TUN-адаптеры Windows/macOS, настольное per-app разделение,
автоматические системные маршруты, kill switch или готовое iOS-приложение.
Android-приложение пока использует свой существующий lifecycle/redialer;
перевод приложения на общий engine этим изменением не сделан.

## Проверки

- Настоящий локальный Hy2: остановка/запуск сервера на прежнем порту,
  повторная аутентификация, рабочий TCP после восстановления.
- Тот же сценарий через SOCKS: слушатель сохраняет адрес, новое соединение работает.
- Сброс во время dial, отмена ожидания потока, закрытие во время authentication,
  backoff, отсутствие попыток после Close.
- Ошибочные пароль, pin и CA завершают запуск без бесконечных повторов.
- `go test -race -timeout 90s ./...`, `go vet ./...`, тесты `breach/mobile`,
  кросс-компиляция общей библиотеки для пяти ОС и desktop CLI amd64/arm64.
- Живой MAX TURN/VPS одним процессом: HTTPS tunnel=200, локальный HTTP direct=200,
  block=отказ SOCKS. SIGTERM завершил процесс с кодом 0; исходный конфиг сохранён,
  временные тестовые файлы и процессы убраны. Как и прежде, для этого VPS был
  явно включён legacy insecure; проверки TLS/pin отдельно выполнены локально.
