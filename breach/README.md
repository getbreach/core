# breach — туннель через TURN-релеи мессенджеров (MAX / WB)

Несёт произвольный трафик через **TURN-релеи мессенджеров** вместо прямого VPS.
Креды на релей добываются из механизма звонков мессенджера, а нагрузка
маскируется под обычный WebRTC-звонок (DTLS-хендшейк → SRTP-медиа). Для внешнего
наблюдателя это соединение с разрешённым сервисом звонков, а не с произвольным IP.

```
[клиент] ──udp/socks──> breach-client ──> TURN-релей ──> breach-server ──> интернет / WG
                        (минт + пул аллокаций)            (публичный UDP :48000)
```

Клиент делает всю TURN-работу (минт кредов, аллокации, keepalive, переминт).
Сервер пассивный: принимает трафик с релея, отдаёт бэкенду и шлёт ответы обратно.
Он провайдеро-независим — не знает, через MAX или WB пришёл трафик.

## Провайдеры

| Провайдер | TURN-инфра | Минт |
|---|---|---|
| **MAX** (`max`) | OK/VK (`155.212.x:19302`, `okcdn.ru`) | конференция или 1:1-звонок |
| **WB** (`wb`) | своя (`176.101.92.x:3478`) | тихий, никого не беспокоит |

**MAX**, `"mintMode"` в конфиге:
- `"silent"` (по умолчанию) — создаёт групповую конференцию (никого не будит) и
  заходит по ссылке; ответ несёт креды.
- `"call"` — ставит реальный 1:1-звонок на `calleeId` (пир получает короткий
  неотвеченный звонок на каждый минт; используй свой второй аккаунт).

**WB** — инициирует и сразу отменяет звонок пиру личного чата; собеседник звонка
не получает, уведомления нет. Нужен именно личный чат (звонок адресуется одному
пиру — из группового некого выбрать). Вход — через WB ID (`-wb-login`).

## Режимы

- **pipe** (по умолчанию) — breach relays UDP, а WireGuard/Hysteria2
  терминируется снаружи. Клиент слушает `-wg-listen`, exit форвардит на `-wg`/`-hy2`.
- **stream** (`-socks`) — breach это весь VPN: клиент поднимает локальный SOCKS5,
  exit сам ходит наружу (QUIC поверх релея). Без WireGuard, без tun, без root.

## Сборка

```bash
cd breach
go build -o bin/breach-server ./cmd/server
go build -o bin/breach-client ./cmd/client
```

## Запуск

**Сервер (VPS, публичный IP):**

```bash
# pipe: бэкенд — WireGuard на udp/51820
./bin/breach-server -listen :48000 -wg 127.0.0.1:51820

# stream: exit ходит наружу сам
./bin/breach-server -listen :48000 -socks 127.0.0.1:1 -clients /etc/breach/clients
```

**Клиент:**

```bash
# MAX, pipe (внешний WireGuard целится в 127.0.0.1:51821)
./bin/breach-client -config config.json -server <VPS_IP>:48000 \
    -wg-listen 127.0.0.1:51821 -streams 4 -mints 2

# WB, stream (локальный SOCKS5, ни WG, ни root)
./bin/breach-client -provider wb -wb-login -wb-session wb.json        # первый вход
./bin/breach-client -provider wb -wb-session wb.json -wb-chat 'chats/<id>' \
    -server <VPS_IP>:48000 -socks 127.0.0.1:1080 \
    -socks-token <пароль> -socks-pin <sha256 серта exit'а>
```

`-streams` — аллокаций на кред, `-mints` — сколько кредов минтить. MAX-конфиг —
см. `config.example.json`; логин по номеру — `-login +7…`.

## Заметки

- Один сервер обслуживает много клиентов: каждый пакет помечен clientID, сервер
  сам разводит клиентов по своим бэкенд-сокетам. Добавить клиента — свой конфиг
  (в идеале свой аккаунт) на тот же `:48000`, per-client конфига на сервере нет.
- **pipe:** WG `MTU = 1280`; TURN-рёбра провайдера (`155.212.0.0/16` у MAX,
  `176.101.92.x` у WB) НЕ заворачивать обратно в туннель — исключить из маршрута
  или запускать breach-client в netns.
- `-turn-transport auto|udp|tcp` — линк клиент↔релей (`auto` = UDP с откатом на TCP).
